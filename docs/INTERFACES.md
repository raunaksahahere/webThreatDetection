## 3. Threat report and commitment (wtd.commitment.v1)
Off-chain document:
```json
{
  "schema": "wtd.threat-report.v1",
  "report_id": "<uuid4 string>",
  "created_at": "2026-11-08T12:00:00Z",
  "kind": "url",
  "classification": "High Risk",
  "rule_id": "R-HIGH-1",
  "indicators": [{"type": "domain", "value": "sbi-kyc-update[.]top"}],
  "findings": [{"id": "url.brand_in_domain", "code": "url.brand_in_domain", "severity": "high", "strength": "moderate", "title": "..."}],
  "evidence_digest": "sha256:<64 hex of JCS(full analysis report)>",
  "summary": "<plain text>",
  "submitter": "<label>"
}
```
Envelope committed on chain:
```json
{"schema": "wtd.commitment.v1", "salt": "<64 lowercase hex, 32 random bytes>", "threat_report": { ... }}
```
- `commitment = SHA-256( RFC8785_JCS(envelope) )` → `bytes32`, written as `0x` + 64 lowercase hex.
- `reportId = SHA-256( UTF-8("wtd.report-id.v1:" + report_id) )` → `bytes32`.
- Classification codes on chain: `0 Inconclusive, 1 Low Risk, 2 Suspicious, 3 High Risk, 4 Confirmed Malicious`.
- Nothing else goes on chain: no URLs, message text, indicators, or personal data. The salt prevents confirming a guessed report by hashing candidates.
- Test vector: `docs/commitment-vectors.json` (generated by the backend; both implementations must reproduce it).

## 4. Contract `ThreatReportRegistry` (Solidity 0.8.38, chain id 31337 local)
Roles: `owner` (two-step transfer) manages `reporter` and `reviewer` sets. Reporters register and revise their own reports. Reviewers set status on reports they did not author.
```
enum Status { Pending, Validated, Disputed, Retracted }
struct Revision { bytes32 commitment; uint8 classification; uint64 timestamp; address author; }
struct StatusChange { Status status; uint64 timestamp; address by; bytes32 noteHash; }

function register(bytes32 reportId, bytes32 commitment, uint8 classification) external;          // onlyReporter; new id; commitment != 0 and unused; classification <= 4
function revise(bytes32 reportId, uint256 expectedRevision, bytes32 commitment, uint8 classification) external; // only original author; expectedRevision == revisionCount; resets status to Pending
function setStatus(bytes32 reportId, Status status, bytes32 noteHash) external;                  // onlyReviewer; reviewer != report author; report exists
function setReporter(address a, bool allowed) external;  // onlyOwner
function setReviewer(address a, bool allowed) external;  // onlyOwner
function transferOwnership(address next) external; function acceptOwnership() external;
function revisionCount(bytes32 reportId) external view returns (uint256);
function getRevision(bytes32 reportId, uint256 index) external view returns (Revision memory);
function statusCount(bytes32 reportId) external view returns (uint256);
function getStatusChange(bytes32 reportId, uint256 index) external view returns (StatusChange memory);
function currentStatus(bytes32 reportId) external view returns (Status);
function reportAuthor(bytes32 reportId) external view returns (address);
function commitmentUsed(bytes32 commitment) external view returns (bool);
event ReportRegistered(bytes32 indexed reportId, address indexed author, bytes32 commitment, uint8 classification);
event ReportRevised(bytes32 indexed reportId, uint256 indexed revision, bytes32 commitment, uint8 classification);
event StatusChanged(bytes32 indexed reportId, Status status, address indexed by, bytes32 noteHash);
event ReporterSet(address indexed account, bool allowed);
event ReviewerSet(address indexed account, bool allowed);
event OwnershipTransferStarted(address indexed previousOwner, address indexed newOwner);
event OwnershipTransferred(address indexed previousOwner, address indexed newOwner);
```
Custom errors for every revert. History is append-only: no function deletes or overwrites a revision or status entry.

Local chain: `anvil --chain-id 31337 --state chain-state/anvil.json --state-interval 10`. Accounts (anvil default mnemonic, public test keys, local only): #0 owner/deployer, #1 reporter (backend signer), #2 reviewer. Deployment output: `deployments/local.json` = `{chainId, address, deployTx, deployBlock, owner, reporter, reviewer, deployedAt}`.

## 5. Independent verifier CLI (`verifier/`, Node 24, viem + canonicalize)
```
node verifier/verify.mjs --envelope <file.json> [--rpc http://127.0.0.1:8545] [--contract 0x...|--deployment deployments/local.json]
```
Recomputes commitment and reportId itself, reads `revisionCount/getRevision/statusCount/getStatusChange` directly from the chain, never calls the backend. Exit codes: 0 = matches latest revision; 2 = matches an older (superseded) revision; 1 = no match / tampered; 3 = chain or input error. Prints chain id, contract, matched revision, block timestamp, status history.
